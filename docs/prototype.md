## Замеры

`?bench=1`: 240 кадров подряд без `requestAnimationFrame` (браузер тормозит его в скрытой вкладке),
в конце ожидание GPU через `readPixels`; время кадра — CPU + GPU. Бюджет при 60 FPS — 16,7 мс.

**Chromium** (в Electron), Apple M3, холст 1600×1200 (DPR 2):

| Сцена | Адрес | мс/кадр | Видеопамять |
|---|---|---:|---:|
| Колония, 96 узлов | `?demo=ui&layout=city/CityScene` | 0,78 | ~36 МиБ |
| Меню строительства, 235 узлов | `?demo=ui&layout=city/construction_menu` | 1,93 | ~66 МиБ |
| Карта без размытия | `?demo=blur&passes=0` | 0,84 | ~57 МиБ |
| Карта + 3 прохода размытия | `?demo=blur&passes=3` | 2,48 | ~57 МиБ |
| Изометрия, 200 юнитов | `?demo=iso&count=200` | 0,68 | ~43 МиБ |
| Изометрия, 500 юнитов | `?demo=iso&count=500` | 1,97 | ~43 МиБ |
| Изометрия, 1000 юнитов | `?demo=iso&count=1000` | 3,30 | ~43 МиБ |

**Safari** — не замерено. Как замерить: `cd web && npm run dev`, открыть адрес из таблицы с `&bench=1`;
результат появится в заголовке вкладки и в консоли.

В оригинале на экране боя до ~150 юнитов (`docs/research/requirements.md`), так что запас по юнитам
большой: время кадра растёт примерно линейно, ~3 мкс на юнита.

## Что выяснилось по ходу

- **Раскладка cocos2d-x переносится формулой.** `toPixiTransform` сверен в тестах с эталонной формулой
  `CCNode::nodeToParentTransform`. Важны умолчания конструкторов: у CCMenu и CCLayer размер экрана,
  anchor (0,5; 0,5) и `ignoreAnchorPointForPosition`, у спрайтов и меток anchor (0,5; 0,5).
- **Прозрачность и цвет в cocos2d-x 2.x не наследуются детьми**, поэтому они применяются к собственному
  содержимому узла, а не ко всему `Container`.
- **Макеты содержат альтернативы**: например, кнопки «Yes» для Google и Game Center лежат друг на друге,
  лишнее прячет код окна. Логика окон — отдельная работа (оценка в `engine-decision.md`).
- **Фон карты** — страницы до 1024², дополненные до полного размера; видимую часть каждой задаёт
  `textures_etc/maps/mission/<карта>.xml`. В прототипе раскладка одной карты задана вручную
  (`render/mapBackground.ts`), для всех карт нужен конвертер (этап 2, #14).
- **Направления на экране** (по кадрам): `ne` — вверх, `e` — вверх-вправо, `se` — вправо, `s` —
  вниз-вправо, `sw` — вниз, к камере; `n`, `nw`, `w` — их отражения. Сектора — `render/visual.ts`.
- **Vite:** путь к `assets/` в конфиге считается от `import.meta.url` — `import.meta.dirname` указывал бы
  во временную папку, куда Vite собирает конфиг.
- **`frames_index.json` весит 13,8 МБ** (0,56 МБ в gzip). Для прототипа это приемлемо, для клиента нужны
  индексы по сценам или категориям.
