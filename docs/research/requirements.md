# Under Fire: Invasion: фактура для требований к браузерному движку

Исследование только на чтение, по оригиналу v1.3.12 (`raw/`, слои накладываются так: patch поверх main, main поверх apk).
Скрипты и промежуточные JSON лежат в `scratchpad/research/requirements/` (далее `R/`). Все цифры ниже получены
этими скриптами. Пометка **[факт]** означает, что значение посчитано по файлам. **[вывод]** означает интерпретацию
фактов. **[предп.]** означает предположение, которое ещё нужно проверить (обычно реверсом `libinferno.so`).

Дополнительный источник: `libinferno.so` не стрипнут и содержит C++-символы (`R/inferno_demangled.txt`, 114 578
строк). Имена классов и методов оттуда подтверждают многие выводы: `IsometricMap`, `CCLayerPanZoom`,
`CRjBatleScheduler` и другие.

Сводный объём после слияния слоёв: 10 175 файлов, 614,5 МБ, из них 455 МБ приходится на текстуры `.pkm.ccz` (`R/merge_index.py`).

## 1. Сцены, экраны, камера, карты

### 1.1. Экраны и режимы
**[факт]** `interface/interface.xml` задаёт четыре сцены с наборами UI-атласов: `splashscreen`, `battle`, `city`,
`worldmap`. Единственная «definition» — `1024x768` (type="tablet"). Макеты ccbi разложены по папкам:
city 99, battle 32, worldmap 11, mainmenu 2, splashscreen 1 (всего 145). Классы сцен в символах: `CityScene`,
`BattleScene`, `ChaptersScene`, `RjWakeUpScene`, `RjPreloader`, `TutorialLayer`. Кроме них там около 60 классов
`Rj*Dialog`.

| Режим | Чем подтверждается |
|---|---|
| Прелоадер / сплэш | `splashscreen/splash.ccbi`, `background/preloader_art` 2048×1152, `common/splash_screen.png` |
| Главное меню | `mainmenu/MainMenuScene.ccbi` |
| Колония (город) | `CityScene.ccbi` и около 95 окон: стройка, апгрейд, армия, технологии, научный центр, тактический штаб, космопорт, наёмники, экспедиции, друзья, почта, квесты, соц. сети, настройки, сохранения, покупки. Секция `scenes`: `city_1`, фон 3392×2452 |
| Галактика / кампании | `worldmap/chapters_menu`, `company_menu`, `mission_menu`, `window_event_map_circles`. Фоны глав 3096×2048, `background/worldmap/back` 2938×2058. `chapters` (5) с кампаниями по координатам x/y, `star_systems` (9) с экспедициями |
| Подготовка к бою | `BattlePrepare.ccbi` (выбор армии), фон-арт `mission_prepare` 2740×1536 |
| Расстановка войск | `PlaceScene.ccbi`, `place_scene_template(_enemy)` |
| Бой | `BattleScene.ccbi`, `shop` (расходники), `turret_widget`, `technology_widget_*`, `win`/`lose`/`mission_end_popup`, `battle_dialog` |
| Магазины | город: `resources_buy_menu`, `credits_buy_menu`, `mercenaries_buy_menu`, `expendables_buy_menu`, `menu_cosmoport` (`spaceport_store` 14); в бою: `shop.ccbi` |

**[факт]** Туториалы (`tutorials`, 12 записей) существуют в трёх вариантах `ratio="133" / "160" / "177"`, то есть для 4:3,
16:10 и 16:9. Арт подготовки к бою имеет размер 2740×1536, что равно 1370×768 в масштабе @2x, то есть 16:9 при высоте 768.
**[вывод]** Макеты свёрстаны под 1024×768. Высота дизайна фиксирована (768), ширина растягивается от 1024 до 1366.
Нужно поддерживать соотношения сторон от 4:3 до 16:9.

### 1.2. Проекция: изометрия
**[факт]**
- Сетка логическая, в клетках: у карт есть `width`/`length`, у объектов `x, y, width, length, height`.
- Размер клетки: `maps/city/cells.atlas` содержит ромбы `border/red/blue` 46×32 px и `empty_cell` 60×40.
- Дорожные тайлы `common/road_tiles/*` (88×56, варианты n/s/w/e/ns/nswe…) собираются автотайлингом. В символах есть `RjCityRoads::getTileWidth/Height`.
- Класс `IsometricMap` в символах: `getIsoPos`, `getRealPos`, `getZoneId`, `getPortalPoint`, `AStarGetG/H`, `getNearDestinationAStar`, `addRenderTexture`, `regenerateShadows`, `regenerateLights`.
- Направления: у зданий n/s/e/w, у юнитов 8 направлений.

**[вывод]** Проекция изометрическая (диметрия). Сетка повёрнута на 45°, ромб клетки около 44–46×32 px, соотношение примерно 1,4:1, а не
классическое 2:1. Оценка по отношению «размер фона / (width+length)»: например, `star_1_map_01` 36×37 клеток на 1613×1162 px дают
44,2×31,8 px на клетку. Точные константы проекции нужно взять из кода.

### 1.3. Формат `config/maps/*.xml`
**[факт]** 155 файлов, из них 121 указан в секции `maps` конфига. 12,9 МБ XML (`R/maps.py`). Структура:
```
<inferno:maps shared="1">
 <map type width length offset_x offset_y>                          # сетка 16–61 × 26–65 клеток (медиана 45×43)
  <visual x y width height src="mission/…" camera_x camera_y/>      # один пререндеренный фон
  <obstacles><obstacle x y width length height visual="buildings/<имя>_<dir>"
             building level direction=n|s|e|w [shoot=1] [visible=0]/>  # 9 690 шт.; медиана 50, максимум 192 на карту
  <zones><zone id x y width length>                                  # 5 323 прямоугольника; медиана 33, максимум 90 на карту
           <portal zone_id from_x from_y to_x to_y/>                  # 37 023 перехода клетка→клетка между зонами
  <paths><path from to next/>                                        # 208 326 записей, до 8 010 на карту
  [<passability><point x y/>]  [<sounds><planet_earth/>…]            # только в 9 картах
```
- Слоёв тайлов нет, TMX не используется. Земля — **одна пререндеренная картинка** размером 1347–3140 × 965–2461 px
  (медиана 1913×1462). Она порезана на тайлы до 1024×1024, раскладку описывает `textures_etc/maps/mission/<src>.xml` (`<back_atlas><frame img x y width height>`).
  Уникальных фонов 120. В 60 картах размер `visual` точно совпадает с размером фона, в остальных фон растянут.
- Зоны — непересекающиеся прямоугольники: на все 116 проверенных карт приходится 10 общих клеток. Они покрывают примерно 26% сетки, то есть проходимые коридоры.
  `paths` — полная таблица следующего перехода «из зоны A в зону B, дальше идти в зону C». В 108 из 116 карт она заполнена для всех n·(n−1) пар.
- **[вывод]** Навигация иерархическая: маршрут по зонам ищется по готовой таблице, затем юнит идёт через точки порталов,
  внутри прямоугольника движется свободно. Для ближних целей есть A* по клеткам (`getNearDestinationAStar`).

### 1.4. Камера
**[факт]** В символах есть `CCLayerPanZoom` (`setMinScale`, `setMaxScale`, `setPanBoundsRect`, `setRubberEffectRatio`,
`setMaxTouchDistanceToClick`) и `RjCameraHelper::moveCamera`, `BattleScene::moveCamera`, `CityScene::moveCameraOnTerritory`.
У туториалов есть шаги `move_camera fromX fromY toX toY duration`, `focus_area`, `focus_element`, `show_arrow`.
В бою игроку подсказывают строкой из ccbi «Передвигайте камеру пальцем».
**[вывод]** Нужны панорамирование с инерцией и упругими границами, зум щипком и колесом в заданных пределах
(значения пределов нужно извлечь из кода), а также плавные программные перелёты камеры.
Мир больше экрана: 1,3–3,1 тыс. px против 1024–1366×768.

## 2. Анимации (`config/visuals/**/*.xml`)

**[факт]** (`R/visuals.py`) 1 151 визуал: buildings 810, territories 95, effects 83, mobs 69, units 64,
citizens 24, turrets 6. Формат: `visual(name, fps, scale, atlases)` → `direction(name, prefix, atlases, offsetX/Y,
width, height, hitArea)` → `state(name)` → `layer(frameCount, frames="3,5,7,…")`.

| Категория | Направления | Состояния | Кадров на состояние (медиана / p90 / максимум) | Слоёв на состояние |
|---|---|---|---|---|
| units (64), mobs (69) | **8**: e, ne, s, se, sw рисуются, **n, w, nw берутся из e, s, se** | 8: run, idle, attack_long, attack_short, die_1..3, ability | 20 / 26–31 / 53 | 1–2 |
| citizens (24) | 8 (так же) | walk, idle, talk, dismiss | 20 / 40 / 74 | 1–2 |
| turrets (6) | 8 (так же) | idle, attack, discharged | 30 / 30 / 30 | 2 |
| buildings (810) | 1 (w) у 632, **4 (n/s/e/w)** у 164, 2–3 у 14 | idle, work, complete (+die у 30) | 1 / 30 / 150 | **до 12**; многослойных 206, анимированных 227 |
| effects (83) | 1 | idle (+attack/die у 7) | 15 / 45 / 150 | 1–2 |
| territories (95) | 1 | idle, ready_to_exprored, exploration, work, complete | 1 | 1 |

- **fps = 15 у всех 1 151 визуалов.** Номера кадров идут через один (3, 5, 7…): рендер делали в 30 fps и брали каждый второй кадр.
- `scale`: 1 у 1 125 визуалов, 0,5 у 18, 0,7 у 7, 1,1 у 1. **[вывод]** Юниты со scale 0,5 нарисованы в двойном разрешении.
  Визуалы `*_mini` переиспользуют текстуры (`name="logos_miner"`) с другим scale.
- **Зеркала.** У всех 163 визуалов с 8 направлениями `prefix` направлений w, nw, n указывает на s, se, e. Кадров w/nw/n в
  большинстве атласов нет: полный набор из 8 префиксов есть только в 61 из 160 наборов текстур.
  **[вывод]** Нужен flipX спрайта вместе с отражением offset. Флага отражения в XML нет, его выводят из пары name≠prefix.
- `hitArea` (полигон) есть у 1 317 из 1 318 направлений зданий и у 94 из 95 территорий, у юнитов его нет.
- Многослойные анимации устроены так: слой 1 — статичная база (один кадр повторяется), слои 2–6 — анимированные детали. Всё рисуется стопкой.
  Режим смешивания в XML не задан. **[предп.]** Везде обычная альфа, но у эффектов и огней может быть аддитивный режим.
- **Связь с атласами и конфигом [факт]:**
  - Юнит в конфиге ссылается на солдата: `units/@soldier` → `soldiers/<type>/visual/@src` (mobs 149, units 123, buildings 48). Дальше идёт `config/visuals/<src>.xml`, а папка текстур берётся из `<visual name>`: `textures_etc/<cat>/<name>/<name>_N.pkm.ccz`. Кадр в атласе называется `/<name>_<prefix>_<frame>.png`.
  - Здание: `buildings/<type>/visual/@src` плюс номер уровня дают `visuals/buildings/<src>_<level>.xml`. На карте указано `visual="buildings/<src>_<level>_<dir>"`. Текстуры лежат в `textures_etc/buildings/<name>/<dir>/<dir>_N`.
  - Звук привязан к анимации через `sound_schemes` (123): visual × направление × состояние → звук с `offset` в мс (бывает отрицательным).
  - Точки выстрела задаёт `tracers_scheme` (43): visual × направление × {attack_long, ability} → x, y.
- **Атласы [факт]** (`R/atlas_scan.py`): 2 685 файлов `.atlas`, 149 951 кадр, из них 129 712 уникальных прямоугольников (одинаковые кадры переиспользуются).
  Строка кадра: `имя x y w h offX offY origW origH [r]`. Кадры обрезаны по содержимому, флаг **`r` (поворот на 90°) стоит у 1 340 кадров**.
  На один набор текстур юнита или моба приходится медиана 2 атласа (чаще всего 2048×1024), максимум 19 (`praetorians_agressor`, `queen_of_swarm`: 18 атласов по 1024²).
  Уникальных ссылок на кадры: units 63 368, mobs 59 703, buildings 32 754.

## 4. Бой

**[факт]** Бой идёт в **реальном времени**: `global_params/ticks_per_second = 30`. `sleep` в behaviors измеряется в тиках: у 252 солдат
длительность `sleep` в обработчике `die` при 30 тиках в секунду равна длительности анимации смерти при 15 fps (медиана отношения 1,00, p10 0,97, p90 1,21).
Символ `CRjBatleScheduler::getTicksCountBeforeNextSpawn` согласуется с этим.

**Структура миссии** (`config/missions/*.xml`: 191 файл, 134 из них используются конфигом, `R/missions*.py`):
- `waypoints`: в миссии 1–6 точек (3 в 86 из 134). Каждая точка — **фаза обороны**. Юниты игрока встают в `defend/point`
  (медиана 9, максимум 35 точек). Маска слота принимает значения 1, 2, 4, 8, 16, 32, 64; **[предп.]** это классы light/medium/heavy/hero/mc_*.
  Фаза запускает свои `script_spawner`. После неё (`after`) приходят подкрепления: `units_support` с `slot_spawner` (drop pod) и новые волны.
  Между фазами доступны расходники (heals/boosts/shields) и восстановление точки (`restore_cost`).
- Волны врагов задаются скриптами: `<script_spawner tag trigger><script><sleep>N</sleep><spawn type x y direction/>…`
  Во всех 191 файлах 22 798 `spawn` и 19 515 `sleep`. В используемых миссиях медиана 10 спавнеров на миссию, максимум 33; типов врагов 105.
- **Число врагов** (сон в тиках, 30 в секунду):
  - за миссию медиана 121, p90 220, максимум 460;
  - за фазу обороны 29 / 64 / 128;
  - появились в любом 10-секундном окне: **19 / 29 / 63**;
  - в 20-секундном окне: **26 / 44 / 112**.
- **[вывод]** На экране одновременно обычно 30–60 юнитов (враги и свои). Ориентир на пик — **около 150 анимированных юнитов**.
  Сверх этого эффекты, трассеры, всплески и полоски здоровья, итого до 1–1,5 тыс. спрайтов в кадре.

**Движение.** По зонам и порталам, с готовой таблицей переходов (раздел 1.3) и A* для ближних целей.
Методы в символах: `CRjUnit::moveTo`, `moveToDefendPoint`. Скорость (`stats/speed`) чаще всего 30, 45, 70 и 20, единицы измерения [предп.] клеток за тик × k.
Юнит поворачивается в одно из 8 направлений.

**Логика юнитов — скриптовый DSL** (`behaviors`, 362 шт., 58 тегов). Обработчики: attack, die, idle, charge, effect. Что в языке есть:
- поток управления: if/then/else, while, and, or, not, переменные, кулдауны, return;
- анимация: animation_play, stop, set, random, if, current, swap_layer;
- выбор целей: query_target, query_targets_in_area, query_targets_in_sector, query_friends; условия distance_to_target_*, can_shoot_target, health_l;
- действия: damage (short/long, pct, damage_type), heal, stun, apply_shield;
- эффекты: cast и cast_visual (264 эффекта классов totem 135, curse 82, voodoo 47; 130 с визуалом), add_splatter_to_target, add_tracer_to_target, shake_screen.

Каждая корутина идёт на своём тике, а урон синхронизирован с кадрами атаки через `sleep`.

**Стрельба и эффекты:**
- Выстрел — мгновенное попадание. Его визуал — **трассер**: линия от точки выстрела (`tracers_scheme`) до цели, `duration`/`blink`.
  Типов трассеров 6: bullet 111 использований, big_bullet 23, big_bullet_blue 14, laser 5, big_laser_red 3, big_laser_blue 3. Атлас `effects/tracers` в PNG.
- **Всплески** (`splatters`, 47): анимация на цели с `duration` в тиках, `vertical` (смещение по высоте), флагами `loop` и `back` (под объектом).
- Тотемы, проклятия и вуду — эффекты на карте со своим behavior.
- Орбитальные удары `cruising_guns` (4, cooldown 300…) и `global_abilities` (reactive_gun, gravibomb, air_strike).

- PvP упоминается в `global_params` (лиги, карты `pvp_*`), но миссий и карт `pvp_*` в конфиге нет. Режим был серверным и не нужен.

## 6. Шейдеры, частицы, звук

**Шейдеры [факт]:** 8 `.frag` и 1 `.vert`, GLSL ES 1.0 в соглашениях cocos2d-x (`CC_Texture0`, `CC_MVPMatrix`).
Большинство работает с «scene texture» по `gl_FragCoord` и `width/height`, то есть это **постобработка кадра через render-to-texture**:
- RadialBlur — радиальное размытие от точки, 5 или 11 выборок (`HI_QUALITY`), используется для орбитального удара;
- Splash — вспышка цветом от точки, для авиаудара;
- Circle — круговое проявление или переход;
- Focus — затемнение всего, кроме круга, для туториала;
- Lines — сканлайны с подкраской;
- GaussianBlur — 5 выборок, одна ось, с .vert;
- Grayscale и Monochrome (сепия).

Параметры анимируются через `RjShaderEffectAction` (`loadShaderFromFile`, `SetQuality`). Из конфига упоминаются только RadialBlur и Splash, остальные вызываются из кода.

**Частицы [факт]:** plist частиц в данных нет, есть только пустой `fileLookup.plist`. Все эффекты — покадровые визуалы: 83 визуала effects и 136 текстур.
Код частиц cocos2d-x в библиотеке слинкован, но **данных для него нет** → **[вывод]** система частиц не нужна.
Box2D (`b2World`) тоже слинкован; используется ли он, неизвестно.

**Звук [факт]** (`R/audio.py`, afinfo): 178 файлов, 47,6 МБ, около 32 минут.

| Группа | Формат | Файлов | МБ | Длительность, мин |
|---|---|---:|---:|---:|
| sounds | wav, 1 канал, 22,05 кГц, 16 бит | 91 | 5,7 | 2,2 |
| actions | wav, 2 канала, 44,1 кГц | 24 | 14,0 | 1,3 |
| actions | mp3, 44,1 кГц, стерео | 39 | 2,4 | 2,5 |
| music (battle 10, city 6, map 1) | mp3 | 17 | 17,3 | 17,9 |
| ambients | mp3 | 7 | 8,3 | 8,6 |

В конфиге: `sounds` 60 записей (kind music/sound), `sound_schemes` 123, громкости по умолчанию music 60, ambient 40, sound 40.
Миссия задаёт плейлист из 5 боевых тем и эмбиента планеты. В оригинале звук шёл через FMOD.

## 7. Требования к движку

### Обязательно
1. **Рендер WebGL (лучше WebGL2) с батчингом спрайтов и поддержкой многих текстур.**
   Пик — около 150 анимированных юнитов (до 112 врагов за 20 с плюс до 35 своих) и до 1–1,5 тыс. спрайтов в кадре.
   В боевой сцене 134–221 текстуры, а изометрическая сортировка перемешивает атласы. Поэтому нужны батчи на несколько текстурных юнитов (8–16) и контроль числа draw call. Canvas2D не подходит.
2. **Конвейер ассетов вне движка** (офлайн-конвертер).
   - Декодировать ETC1 с альфой из нижней половины: 3 405 текстур.
   - Выдать PNG/WebP и/или KTX2. ETC1 на десктопных браузерах в общем случае недоступен [предп.: расширения etc1/etc есть в основном на мобильных GPU].
   - Импорт атласов Inferno: trim-смещения, **повёрнутые кадры (1 340)**, общие прямоугольники.
   - Тайловые фоны по back_atlas до 1024².
   - Лимит текстуры 2048: ему соответствуют все, кроме 2 legacy.
3. **Управление памятью текстур**: ленивая загрузка по сцене, выгрузка, LRU, выбор HD или SD для UI.
   Всего 8,6 ГиБ RGBA, бой 0,3–0,65 ГиБ, городские окна 903 МиБ HD. Заодно освобождать CPU-копии декодированных картинок.
4. **Покадровая анимация по формату visuals.** 15 fps, до 12 слоёв в стопке, 8 направлений с **flipX для n/w/nw** (163 визуала),
   смещения по направлениям, `scale` 0,5/0,7, переключение состояний и длительность анимации для логики.
5. **Изометрический мир**: сетка в экран (ромб около 46×32), сортировка по глубине для многоклеточных объектов (от 1×1 до 8×8, не только квадраты: 4×8, 2×4),
   клик по полигонам `hitArea` (1 317 направлений зданий), слой пререндеренного фона до 3140×2461 (город 3392×2452).
6. **Камера**: панорамирование с инерцией и упругими границами, зум щипком и колесом (`CCLayerPanZoom` min/max), программные перелёты (`move_camera`), тряска (22 `shake_screen`).
7. **Логика с фиксированным шагом 30 тиков в секунду**, отвязанная от рендера (60 Гц с интерполяцией), и **VM для DSL behaviors**: 58 тегов, корутины со `sleep` в тиках.
   Это собственный код, не функция движка, но движок не должен навязывать свой цикл.
8. **Навигация**: граф зон и порталов с таблицей переходов (до 90 зон, до 8 010 путей на карту) и A* по клеткам.
9. **UI-слой по ccbi**: конвертер ccbi→JSON (формат v5 + расширение Inferno) и дерево узлов с anchor/scale/position/visible.
   - виджеты: спрайт, TTF-лейбл с переносом (887), кнопки (296 + 165), чекбоксы (40), скролл-списки и таблицы с клиппингом (74), радиальный или линейный прогресс (21), rich-text (216);
   - твины opacity/scale/position;
   - адаптация к экранам от 4:3 до 16:9 при высоте 768.
10. **Текст**: TTF с кириллицей (Play*), разметка `<font color>`, `<br>`, `<b>` (около 180 строк), формулы `{…}` и плюралы. Нужно для `CCTextLayout`.
11. **Аудио на WebAudio**: шины music/ambient/sound с громкостями, много одновременных коротких звуков с ограничением голосов
    (на каждую атаку любого из 150 юнитов), старт со смещением в мс относительно анимации, плейлисты и кроссфейд, wav и mp3, разблокировка по первому жесту.
12. **Ввод**: мышь и тач (тап, перетаскивание, щипок, долгое нажатие — «нажми и удерживай иконку юнита»).
13. **Сохранения и реальное время**: IndexedDB или localStorage, таймеры по часам (1 329 `timings` от 0 до 30 суток, медиана 2 ч).

### Желательно
1. **Render-to-texture и постобработка**: 8 шейдеров GLSL ES 1.0 переносятся почти как есть.
   Нужны для орбитального и авиаудара, фокуса туториала, размытия под окнами. Без них игра работает, но теряет эффекты.
2. **Сжатые GPU-текстуры (KTX2/Basis → BC7, ASTC, ETC2)**: VRAM в бою уменьшится с 300–650 до примерно 100–160 МиБ.
   Альтернатива — даунскейл юнитов со scale 0,5 (18 визуалов, текстуры в двойном разрешении).
3. **Маски и клиппинг** через stencil или альфа-маску: `CCMaskSprite`, `CCProgressTimer`, скроллы.
4. **Режимы смешивания** помимо обычной альфы (аддитивный для огней и эффектов [предп.]). Простые источники света: 2 фонаря с color, size, brightness.
5. **Поддержка HiDPI**: HD-арт сделан для 2× от 1024×768. **Прелоадер с прогрессом**: на диске 455 МБ текстур.
6. **Компактная упаковка данных**: config.json весит 14 МБ (в gzip 0,41 МБ), XML карт 12,9 МБ (в основном таблицы путей, их можно пересчитать при загрузке).

### Не требуется (по данным)
- Частицы: нет данных частиц. Скелетная анимация: нет. TMX и тайловые слои: нет. 3D: нет. Физика: использование Box2D не подтверждено.

**Про выбор стека (кратко).** Пункты 1, 3–7 и 11–12 в той или иной мере покрыты и в PixiJS, и в Phaser 3.
В обоих придётся писать своё: изометрическую сортировку, VM behaviors, навигацию, UI-слой из ccbi (самая большая работа: 145 макетов, 9 кастомных виджетов)
и конвейер ассетов. Решающими остаются управление памятью текстур, постобработка и то, насколько удобно строить собственный UI-слой.
