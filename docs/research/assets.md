# Under Fire: текстуры, атласы и объём ассетов для браузера

Исследование от 29.09.2026. В `raw/` и в проекте ничего не менялось. Все скрипты, данные и картинки лежат в
`scratchpad/research/assets/` (далее `assets/`). Окружение: Mac arm64, 8 ядер, 8 ГБ ОЗУ. Отдельный venv
`assets/.venv` (uv, Python 3.12.3): texture2ddecoder 1.0.6, Pillow 12.3.0, numpy 2.5.3, pyoxipng 9.1.1,
pngquant 3.0.3 (пакет pngquant-cli), imageio-ffmpeg 0.6.0 (ffmpeg 7.1 с libopus, aac_at и libmp3lame) и brotli 1.2.0.
cwebp 1.6.0 взят из Homebrew, он уже был установлен. Глобально ничего не ставилось.

Обозначения: **[проверено]** — подтверждено командой, числом или картинкой; **[предположение]** —
вывод без прямой проверки.

## Кратко

- **Альфа — подтверждено.** У всех 3 405 текстур с удвоенной высотой нижняя половина строго серая:
  R=G=B у 100% пикселей, максимальная разница каналов 0. Это маска, выровненная с цветом пиксель в
  пиксель. Альфа прямая, не premultiplied. У 703 текстур (все карты и фоны) маска целиком равна 255, то
  есть альфа им не нужна. 98 текстур без удвоения — непрозрачные изображения.
- **Атласы — подтверждено с уточнениями.** Поля такие: `x y w h` — прямоугольник в цветной половине
  страницы, `ox oy` — смещение обрезанного кадра от **левого верхнего** угла исходного кадра (Y вниз),
  `W H` — исходный размер кадра. Сверх гипотезы найден 10-й необязательный флаг **`r`** (1 340 кадров из
  149 933). Такой кадр хранится повёрнутым на 90° по часовой, а пары `w,h` и `ox,oy` у него записаны
  переставленными.
- **Объём браузерного комплекта:** около **439 МБ** при WebP q90 + WebP-иконках + Opus + сжатых данных.
  Сейчас оригинал занимает 559 МБ, PNG без оптимизации — 1,21 ГБ.
- **На старте:** примерно **17–21 МБ** (плюс JS-код) и ещё около 4 МБ до первого боя.
- **Хостинг.** Рекомендую держать на GitHub Pages только код, а ассеты не публиковать, а собирать в
  браузере из XAPK, который игрок приносит сам (см. раздел 5). Если публиковать ассеты всё же решено,
  подходит Cloudflare Workers/Pages или R2. GitHub Releases не отдают CORS, а LFS не работает с Pages.

## 1. Декодер `.pkm.ccz`

**Цепочка** (реализация — `assets/pkm.py`): заголовок `CCZ!` → zlib → PKM → ETC1 → RGB → разбиение на
цвет и альфу. Декодер ETC1 — `texture2ddecoder.decode_etc1`: он возвращает BGRA, альфа равна 255.

**Заголовки всех 3 503 файлов [проверено]** (`assets/texture_headers.json`):

- CCZ: сигнатура `CCZ!`, тип сжатия 0 (zlib) и версия **2** у всех, резерв 0, длина совпадает с распакованной.
- PKM: `PKM 10`, формат 0 (ETC1 RGB) у всех. Размер данных у всех ровно `(W/4)·(H/4)·8` байт.
- Высота: у 3 405 закодированная высота ровно вдвое больше исходной, при этом ширина совпадает, а исходная
  высота кратна 4, так что половины не делят блоки 4×4. У 95 высота не удвоена. Ещё у 3 иконок зданий
  456×280 при исходных 455×279 — это просто дополнение до кратного 4.
- Все размеры — степени двойки, кроме этих 3 иконок и `maps/city/city_1` (3392×2452).
- Всего: 455 МБ CCZ, 2,28 ГБ распакованного ETC1, 4 563 Мпикс закодировано, из них 2 299 Мпикс видимых.
- Уникальных по содержимому 3 336. 167 файлов — побайтовые дубли (9,1 МБ CCZ). Например,
  `buildings/X/w_1.*` совпадает с `buildings/X/w/w_1.*`, а одинаковые тайлы встречаются в разных картах.

**Скорость [проверено]:** текстура 2048×2048 декодируется за 0,03 с. Проверка серости по всем 3 405 текстурам
заняла 14 с в 6 процессах. Полный прогон (декод и 5 кодировок) — 648 с.

**Образцы** (`assets/samples/`): для каждого есть `*_etc_full.png` (сырой декод обеих половин),
`*_rgba.png` и `*_preview.png` (верх | низ | RGBA на шахматке).

## 2. Гипотеза про альфу

**Подтверждена [проверено].**

1. **Серость.** У всех 3 405 текстур с удвоением нижняя половина строго серая: R=G=B у 100% пикселей,
   максимальная разница каналов 0 (`assets/gray_check.py`, `gray_check.json`).
2. **Выравнивание.** Для 8 образцов спрайтов и UI пересечение «альфа > 128» и «цвет не чёрный»
   максимально при нулевом сдвиге среди сдвигов ±2 px (`samples/samples_report.json`). Для эффекта
   air_strike эта метрика неинформативна из-за свечения, для карт и фонов — из-за альфы 255.
3. **Визуально.** В превью силуэты маски совпадают со спрайтами. Взрывы превращаются в мягкое свечение,
   тени — в полупрозрачные. При увеличении ×4 на белом и пурпурном фоне нет тёмной или цветной каймы:
   `samples/unit_bomb_pig_edges_zoom.png`, `ui_city_scene_edges_zoom.png`.
4. **Альфа прямая, не premultiplied.** У видимых пикселей часто max(RGB) > A+16: 73% у building_champion,
   62% у air_strike. При premultiplied такое невозможно. Под `alpha=0` цвет в основном чёрный: медиана
   95% пикселей по 2 684 текстурам, 10-й перцентиль 70%. **Следствие:** при билинейной фильтрации без
   premultiply на краях возможна тёмная кайма, поэтому текстуры нужно премультиплицировать при загрузке
   (`UNPACK_PREMULTIPLY_ALPHA_WEBGL`; в PixiJS это, насколько мне известно, режим по умолчанию
   **[предположение]**).
5. **У 703 текстур маска целиком равна 255:** maps/mission (523), background/mission_prepare (102),
   maps/city (61), background/worldmap (9), preloader_art (4) и 4 иконки. Для браузера их стоит хранить
   как RGB — это главный выигрыш в lossy-WebP.
6. **Шум ETC1 в альфе.** 0–7% пикселей имеют альфу 1–8 из 255 вдали от спрайтов (дальше 4 px от
   альфы > 32). Это хвосты теней и шум ETC1: он не виден, трогать его не нужно.
7. **98 текстур без удвоения** — непрозрачные изображения, альфа им не нужна:
   - 92 иконки `icons/buildings`: здание на фоне, 256² или 455×279;
   - `maps/mission/star_1_map_09` (2048², мини-карта с чёрной виньеткой) и `city_map_final_fixed` (4096²);
   - `maps/city/city_1` (3392×2452) — то же изображение, что склейка 12 тайлов `city_1_*`: PSNR 39,6 дБ,
     средняя разница 0,43 уровня, то есть сжато отдельно. Одну копию можно не хранить;
   - `road_texture` — тайл дороги 256²;
   - `effects/reactive_gun*/..._alpha` — чёрный фон с яркими полосами. **[Предположение]** Они рисуются
     аддитивно, а `_alpha` в имени — это режим смешивания, а не маска.

## 3. Гипотеза про `.atlas`

**Подтверждена с уточнениями [проверено]** (скрипты `assets/atlas*.py`, картинки в `assets/atlas_frames/`).

**Формат строки:** `/имя.png⇥x⇥y⇥w⇥h⇥ox⇥oy⇥W⇥H⇥[r]`, окончание строки CRLF. Первая строка — `textures: X.png`.
Всего 2 685 атласов (уникальных 2 630), 149 933 кадра, 129 694 уникальных прямоугольника: одинаковые кадры
упаковщик хранит один раз.

- **Обычный кадр.** `x y w h` — прямоугольник в цветной (верхней) половине страницы. `ox oy` — позиция
  обрезанного кадра в исходном кадре от левого верхнего угла, Y вниз. `W H` — исходный размер, он же
  `width/height` направления в `config/visuals/*.xml` (у bomb_pig 128×125). Условие `ox+w ≤ W, oy+h ≤ H`
  выполняется у всех кадров.
- **Флаг `r` (1 340 кадров, 0,9%).** Кадр хранится повёрнутым на 90° по часовой, а поля заданы в
  повёрнутой системе. Реальный размер — `h×w`, реальное смещение — `(oy, ox)`. Восстановление: повернуть
  область на 90° против часовой и поставить в `x=oy, y=ox`. Доказательства:
  - в этой интерпретации условие выполняется у всех 1 340 кадров, а «как есть» ломается у 559, «поменять
    только w и h» — у 351;
  - при сравнении с соседними кадрами той же анимации вариант выигрывает в 1 538 из 1 576 случаев
    (97,6%), остальные — ничьи с разницей ≤ 0,02 или кадры взрывов;
  - прямой пример: `research_center_3_e_45 (r)` имеет `w=180 h=146 ox=7 oy=54`, а соседний `e_43` —
    `w=146 h=180 ox=54 oy=7`.

  Картинки: `rotated_frames_check.png`, `cut_rotated_research_center_e_45.png`.
- **Начало отсчёта — левый верхний угол.** По анимациям из `visuals` соседние кадры ближе друг к другу
  при отсчёте сверху в 55 визуалах из 57 (1 ничья, 1 противоположный с 7 парами кадров). Независимое
  подтверждение даёт якорь: `(-offsetX, -offsetY)` направления и полигон `hitArea` относительно него
  точно накрывают спрайт. Для `acid_barrel_1_1` hitArea занимает x 0…60, y −38…20, а спрайт — x +4…+53,
  y −36…+18 (`cut_building_acid_barrel_w_0.png`). У юнита якорь попадает под ноги
  (`cut_unit_bomb_pig_e_27.png`).
- **Обрезка плотная.** Зазор между краем кадра и bbox альфы > 0: 0 px у 48–65% сторон, 1 px у 22–39%,
  2 px и больше примерно у 10% (выборка 250 атласов). **[Предположение]** Зазор в 1 px — это ETC1,
  обнуливший слабую альфу.
- **Упаковка без отступов.** У 95% обрезанных кадров соседний прямоугольник вплотную (0 px). В UI-атласах
  кадры не обрезаны и стоят с шагом 2 px (`cut_ui_button_cross.png`). При масштабировании с билинейной
  фильтрацией возможно просачивание соседних кадров. В оригинале было то же самое; если появятся швы,
  при сборке можно переупаковать с extrude 1–2 px.
- **Аномалии, которые должен учесть загрузчик:**
  - `effects/tracers/tracers.atlas` ссылается на обычный `tracers.png`, а не на pkm;
  - `maps/city/cells.atlas` в заголовке называет `atlas.png`, хотя текстура — `cells.pkm.ccz`, и имена
    кадров идут без `/`. Текстуру надо искать по имени файла атласа, а не по заголовку;
  - 4 кадра `interface/*/city/tutorial_menu.atlas` выходят за страницу на 2 px (x=2, w=2048) — обрезать
    по краю;
  - 73 кадра пустые (w или h равно 0), 957 кадров не обрезаны;
  - имена кадров не уникальны между HD- и SD-интерфейсом, поэтому пространство имён нужно вести по атласу.
- **Текстуры без атласа (820):** maps/mission (535), background/mission_prepare (102), icons/buildings (96),
  maps/city (71), background/worldmap (9) и другие. Большие картинки нарезаны на тайлы и описаны XML
  `back_atlas` (`<frame img x y width height>`), остальные используются целиком.

**Перевод в JSON-формат TexturePacker (для PixiJS или Phaser)** **[предположение — проверить в выбранном
движке на `research_center_3_e_45`, эталон есть]**:

- обычный кадр: `frame {x,y,w,h}`, `spriteSourceSize {x:ox, y:oy, w, h}`, `sourceSize {W,H}`,
  `trimmed = (w,h) ≠ (W,H)`;
- кадр с `r`: `rotated: true`, `frame {x, y, w:h, h:w}`, `spriteSourceSize {x:oy, y:ox, w:h, h:w}`;
- `pivot = (-offsetX/W, -offsetY/H)` из направления в `visuals`.

## 4. Объём

Методика: `assets/convert_all.py` декодирует каждую уникальную текстуру и кодирует её пятью способами.
Файлы не сохраняются — пишутся только размеры в `sizes_textures.jsonl`. Маски, равные 255 везде,
кодируются как RGB. Кодировки:

- PNG через Pillow, zlib 6;
- oxipng `-o2`;
- pngquant `--quality=65-90 --speed 3`; если качество недостижимо, берётся oxipng — так было у 58 из 3 336;
- `cwebp -lossless`;
- `cwebp -q 90` (альфа остаётся lossless).

| Старт со всем HD-интерфейсом (+battle, worldmap) | 16,4 (21,6) | 1,0 | 1,8 (2,9) | ~2 | **~21 МБ** |

К этому добавляется JS-код движка. Сеть не узкое место, **узкое место — видеопамять.** Стартовые текстуры
в RGBA8 занимают 1,05–1,36 ГБ (263–339 Мпикс), почти всё приходится на HD-интерфейс: 92 текстуры,
313 Мпикс, в основном 2048² с пустыми областями. Весь комплект занял бы 8,6 ГБ. В оригинале ETC1 занимал
0,5 байта на пиксель на каждую половину. Что с этим делать:

- грузить и выгружать UI по экранам;
- на мобильных использовать SD-интерфейс (81 Мпикс);
- позже перевести тяжёлые категории на KTX2/Basis — это не измерялось.

Что это значит для рекомендуемого комплекта (438,6 МБ, около 10 тысяч файлов, самый большой 1 МБ):

- **GitHub Pages** технически вмещает комплект. Но ассеты пришлось бы коммитить в git: история раздувается,
  и после пары обновлений репозиторий перевалит за 1 GB. 100 GB трафика в месяц — это около 230 полных
  скачиваний.
- **Releases** не подходят для прямой загрузки из браузера: нет CORS.
- **LFS** не отдаётся через Pages, а 10 GiB трафика — это около 20 клонов.
- **Cloudflare Workers/Pages** вмещают комплект с запасом (лимит — 20 тысяч файлов по 25 МиБ), статика
  бесплатна и не ограничена, а заливка через `wrangler` идёт прямо из локальной сборки, минуя git.
  **R2** — альтернатива для крупных редко меняющихся данных: 10 GB бесплатно, но нужны свой домен и CORS.

**Рекомендация.** Главное ограничение не техническое. В README проекта сказано, что графика, звук и данные
игры принадлежат правообладателям и в репозиторий не входят. Любая публичная раздача сконвертированных
ассетов — это их распространение (на GitHub, кроме того, есть риск DMCA для всего репозитория).

1. **Основной путь — «свой XAPK».** На GitHub Pages лежит только клиент.
   - Игрок выбирает свой XAPK или OBB. `main.13` (480 МБ) и `patch.59` (154 МБ) — обычные ZIP с Deflate и
     Stored **[проверено `unzip -v`]**.
   - Клиент читает нужные записи через `File.slice` по центральному каталогу ZIP. CCZ распаковывается через
     `DecompressionStream('deflate')`, это zlib-обёртка. ETC1 декодируется в Web Worker (JS или WASM),
     маска берётся из нижней половины. Всё кэшируется в OPFS или IndexedDB.
   - Декод дешёвый: 0,03 с на 2048² в нативном коде. **[Предположение]** В WASM в пределах ×2–3.
   - Экономия на хостинге — 100%, и это согласуется с политикой README.
2. **Если публиковать ассеты всё же решено** (с разрешения или для закрытого теста):
   - хостинг — Cloudflare Workers Static Assets или Pages через `wrangler deploy` из локальной сборки,
     либо R2 со своим доменом;
   - формат — WebP q90 (RGB для карт и фонов, RGBA для спрайтов), атласы в JSON, звук Opus с запасным AAC
     (в Safari на macOS поддержка Opus частичная, [caniuse](https://caniuse.com/opus)), данные в JSON с
     brotli или gzip от CDN;
   - раскладка — сохранить дерево каталогов (лимит 3 000 записей в каталоге GitHub), имена с хешем
     содержимого и манифест (дедупликация 166 путей), `Cache-Control: immutable`, Service Worker.
3. **Загрузка в клиент в любом варианте:**
   - пакетами по сценам: старт около 17–21 МБ, миссия несколько МБ, постройки по требованию;
   - premultiply при загрузке текстур;
   - выгрузка текстур при уходе со сцены;
   - SD-интерфейс для мобильных;
   - при швах на кадрах — переупаковка атласов с extrude.
